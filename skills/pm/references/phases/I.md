# I. リリースする（移行・受入れ・運用引継ぎ）

この段階の問いは「出していいか、どう出せば壊れないか、運用できるか」。

## 39 リリース計画・段階的ロールアウト図

- 先に調べる: 配信の仕組み（ストアの段階公開・機能フラグ・デプロイ設定）
- 聞くこと: 各段階の対象と期間 / 次へ進む数値の条件 / 止める手段
- 良い状態: 各段階の「次へ進む条件」が数値。異常時に止める・無効化する手段が実際にある
- 落とし穴: 止める手段が無いのに段階公開を書く

## 40 Go / No-Goチェックリスト

- 先に調べる: 31 の品質目標、未解決の重大バグ（issue）、CI の状態、42 の引継ぎ状況。調べて確定できた項目はチェックを入れる
- 聞くこと: 判定者 / 未達項目がある場合の扱い
- 良い状態: 判定項目がリリース直前ではなく事前に合意されている。未達時の扱い（条件付き Go の条件）が決まっている
- 落とし穴: 確認していない項目にチェックを入れる

## 41 移行・互換性マトリクス

- 先に調べる: API のバージョン・クライアントの最小対応バージョン・強制アップデートの仕組み
- 聞くこと: 旧バージョンの利用率 / 旧 API を止める条件
- 良い状態: 出す順序と、旧 API を廃止する判断の条件が書かれている

## 42 運用・保守引継ぎ資料

- 先に調べる: インフラ構成・デプロイ手順・監視設定・既知のバグ（issue）
- 聞くこと: 受け手 / 権限を渡す範囲 / 緊急連絡先
- 良い状態: 各項目の置き場所が書かれ、受け手が「済」を確認している
