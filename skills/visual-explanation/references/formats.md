# 見せ方と template.html の部品

どの変更にどの見せ方を使うかの表は rule `visual-explanation` (`.claude/rules/visual-explanation.md`) を正とする。ここには、選んだ見せ方を `assets/template.html` のどの部品で描くかだけを書く。

複数に当てはまるときは、読む人が最初に知りたいもの (たいてい「何が変わるか」) を 1 枚目にする。

| 見せ方 | template.html の部品 |
|---|---|
| Before / After | `.compare` + `.label.before/.after` |
| 仕組みの図 (タイムライン・競合の順番) | `.timeline` |
| 1 枚まとめ (コード + 実行結果) | `pre` を 2 つ (コード / 出力) |
| 消えるもの / 残るもの | `.compare` (ラベルを「消える / 残る」に) |
| 現状と目指す姿 (チケット) | `.compare` (ラベルを「いま / 目指す姿」に) |
| GIF (画面収録できる) | 使わない。画面収録をそのまま使う |
| GIF (画面収録できない) | 下の「実ログから GIF を作る」 |
| diff・`<details>` の出力・画像なし | 使わない。本文に直接書く |

## 1 枚の作り方

### 1. 1 文を決めてから描く

描き始める前に「この 1 枚で何を伝えるか」を 1 文で書く。それがそのまま `<h2>` になる。

- 1 文が書けないなら、まだ図にする段階ではない。本文の文章で書く。
- 2 つ言いたくなったら section を分ける (1 section 1 メッセージ)。

### 2. 型を選ぶ

PR の変更なら上の表で選ぶ。チケット・レポートなど変更以外の説明は、伝えたいことから型を 1 つ選ぶ (1 枚に 1 つの型)。

| 伝えたいこと | 型 | template.html の部品 |
|---|---|---|
| 1〜3 文で済む / Yes・No / コードそのものが答え | 図にしない | — (本文に書く) |
| 2〜3 個の選択肢の比較 | カード横並び | `.compare` |
| 4 個以上・4 軸以上の比較 | Markdown の表 | — (画像にしない) |
| 選択肢から 1 つを勧める | 推奨度付きカード | `.option` + `.score` |
| 処理の順番・手順 | 手順 | `.steps` (要の 1 つに `.key`) |
| 時刻つきの順番・競合 | タイムライン | `.timeline` |
| モジュール・レイヤー・依存 | 構造図 | `.card` を縦に積む |
| ディレクトリ・ツリー | 階層ツリー | `pre` |
| 実測の数値の比較 | 横棒 | `.bars` |
| 長い議論の結論 | キーメッセージ | `.conclusion` |

迷ったら: 順番があれば手順、比べるならカード横並び。

### 3. 書く

- **文字量**: 図の中は見出しと短いラベルだけにする。説明の文章は本文に書く。
  - 1 枚に入れる文は見出しと説明文の 2 つ (多くても 3 つ)。
  - 見出しは 5 単語前後 (最大 8 単語 / 40 文字)。説明文は 10 単語前後 (最大 30 単語 / 50 文字)。
- **色**: 意味のある色だけ、1 枚で 2〜3 色まで。強調は `--accent`、OK / NG は `--ok` / `--ng`。それ以外は `--text` / `--muted` / `--surface` の灰色系。
- **等幅**: コード・ファイル名・モジュール名・関数名・コマンドは `var(--mono)`。
- **注目の行**: コードを載せるときは、見てほしい 1 行 (最大 3 行) の上に `⭐️ <30 文字以内の一言>` のコメントを置く。
- **推奨度**: 選択肢を並べるときは、各案の名前 (20 字以内) の横に `推奨度 N / 10` を付け、勧める案を先頭にする。
- `.lead` に「何と何を比べたか / 何の順番か」を書く。
- `.note` に撮り方 (画面収録 / 実ログから描いた再現 / headless 描画) と、PR・コミット範囲・コマンドを書く。
- 実際の実行・実データから作る。モックは作らない。
- 色は `:root` のトークンだけを使う (hex を直書きしない)。プロジェクトにデザインシステムがあれば、トークンの値をそちらに合わせる。

### 4. 撮る前のセルフチェック

`capture.mjs` が見出しの数と長さ・横のはみ出しは `WARN:` で知らせる。それ以外は目で確かめる。

- 1 文メッセージを言えるか。
- 図の中に説明の文章を書いていないか。本文で図の中身を繰り返していないか。
- 色が 3 色を超えていないか。意味のない色を使っていないか。
- ライト / ダークの両方で読めるか。

## 実ログから GIF を作る

クラウドのセッションなど画面収録できない環境では、実際の実行ログを 1 コマずつ描いて GIF にする。

1. 実際に実行して、出力 (端末の出力・MCP の呼び出し記録など) を保存する。
2. 1 コマ 1 section で、ログを先頭から少しずつ増やした `pre` を書く。id は `frame-01`, `frame-02`, ... のように連番にする。
3. ライトだけ撮る: `node capture.mjs <html> <out-dir> --schemes=light`
4. GIF にする: `bash make-gif.sh <out.gif> <out-dir>/frame-*-light.png`
5. 本文には「実ログから描いた再現 (画面収録ではない)」と、元にしたログ・コマンドを書く。
