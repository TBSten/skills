# 見せ方の選び方

変更・内容の種類から見せ方を 1 つ選ぶ。複数に当てはまるときは、読む人が最初に知りたいもの (たいてい「何が変わるか」) を 1 枚目にする。

| 変更・内容 | 見せ方 | template.html の部品 |
|---|---|---|
| 見た目・出力が変わる | Before / After を実物で並べる (同じ入力で main とこのブランチを撮る) | `.compare` + `.label.before/.after` |
| バグ・原因の説明 | 仕組みの図 (タイムライン・競合の順番など) | `.timeline` |
| 新しい API・機能 | 1 枚まとめ (書けるコード + 実行結果) | `pre` を 2 つ (コード / 出力) |
| 動くもの (CLI・UI) | 実際の実行から作った GIF / 動画 | 画面収録。HTML は使わない |
| 削除・移動 | 消えるもの / 残るものの図 | `.compare` (ラベルを「消える / 残る」に) |
| チケットの起票 (課題・提案) | 現状と目指す姿を並べた図 1 枚 | `.compare` (ラベルを「いま / 目指す姿」に) |
| 数行の変更 | diff のコードブロック (画像は要らない) | 使わない。本文に ```diff |
| 見た目がない | 実際の出力を `<details>` に入れる | 使わない |
| CI だけ・設定だけ | 画像なしでよい。確かめ方を書く | 使わない |

## 1 枚の作り方

- 1 section 1 メッセージ。`<h2>` にそのメッセージを 1 文で書く。
- `.lead` に「何と何を比べたか / 何の順番か」を書く。
- `.note` に撮り方 (画面収録 / 実ログから描いた再現 / headless 描画) と、PR・コミット範囲・コマンドを書く。
- 実際の実行・実データから作る。モックは作らない。
- 色は `:root` のトークンだけを使う。プロジェクトにデザインシステムがあれば、トークンの値をそちらに合わせる。
