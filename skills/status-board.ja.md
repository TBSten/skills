# status-board

**いま抱えている作業を 1 枚の HTML にまとめる**スキル。 依存グラフの SVG 図とエピック別カンバンで、
「人間待ちはどれか」「次の一手はどれか」が一目で分かる状態を作る。

![status-board が生成した HTML の例](./status-board-overview.png)

上の例で言うと:

- **上段の図** — 左から右へ依存が流れる。 破線の枠がエピック (`廃止` / `manifest driven development` /
  `構想`)、 赤い六角形が 🙋 人間待ちで、 金色の `NEXT 1` が次の一手。
  **未決や人間待ちは止めている相手の真下に置かれ、 赤い破線が下から上へ突き上がる**
  （横に長い線で図を横断させるより 「これが止めている」 が一目で分かるため）
- **下段のカンバン** — エピックごとに 1 段。 その段が実際に持っているステータス列だけが出る
- **右の詳細パネル** — 選択中のチケットの本文・依存 (前提 / ブロックされている / 次)・関連 PR
- **上の絞り込み行** — ステータスのチップ。 押すと図では薄く、 カンバンでは列ごと消える

## インストール

```sh
gh skill install tbsten/skills status-board
```

## 概要

GitHub の PR / issue、 ローカルブランチ、 そして**会話の中で出た未決事項や人間待ち**を集めて、
`.local/status-board/<yyyy-MM-dd-HH-mm>.html` に **standalone な 1 ファイル**を出力する。
CSS も JS も全部インラインなので、 ブラウザで開くだけで動く。

図はドラッグでパン、 ホイールでズームでき、 引くと**意味的ズーム**で詳細行が落ちて全体が読める。
エピックのラベルを押すとその塊が 1 ノードに畳まれ、 依存線は自動でその箱に繋ぎ替わる。
図だけを SVG / PNG で書き出すこともできる。 Shift+クリックで複数のチケットを選べば、
**選んだところだけを浮かせた図**が書き出せる（後述）。
「全画面」ボタンで図だけをビューポート一杯に広げられる（もう一度押すか Esc で戻る）。

**ぱっと見で分かるべき 2 点**を最優先に設計している: 🙋 六角形 = 人間待ち、 金色の NEXT n = 次の一手。

## 使うべきタイミング

- 複数の PR や作業が並行していて、 **何が止まっているか**を把握したい
- stacked PR の詰まりを見たい
- 進行中の移行作業の残りを俯瞰したい
- ユーザーに**確認したいことをまとめて投げたい**（後述の確認欄）
- 状況を人に見せる 1 枚が欲しい

## 確認欄 — ブラウザで回答を受け取る

`ask` を持つ item と人間待ちのノードには、 詳細パネルに「確認したいこと」「回答」の textarea が出る。

- 回答を書くと、 図のチップが `🙋 人間待ち` から `✓ 回答済` に変わり、 カンバンのカードに緑の ✓ が付く
- 内容は `localStorage` に保存される。 キーは**ボード名 + item の id** なので、
  **次に生成し直した HTML でも同じ id なら引き継がれる**
- `file://` で直接開くと `localStorage` が使えないブラウザがある。 回答を残したいときは
  同梱の `serve.mjs` 経由で開く

エージェントに「確認したいことを ask に入れて」と伝えると、 論点を選択肢つきで並べてくれる。

## 複数選択 — PR に貼る図を作る

**Shift+クリックで複数のチケットを選べる。** 図でもカンバンでも同じで、
通常のクリックは今まで通り「その 1 件だけ」の選択のままになる。
選択やフィルターの表示状態は URL の query parameter (`?sel=` など) に入るので、
URL をコピーすればそのままの表示を共有できる。

- 複数選んでいる間、 右の詳細パネルは**選択中の一覧**になる。
  行を押すとその 1 件の詳細に潜り、 ✕ で選択から外れる
- 選んだまま `SVG` / `PNG` を押すと、 **選んだものだけを浮かせた全体図**が書き出される。
  選択とその隣接以外は薄く沈み、 **選択したチケットに繋がる依存線**（片端だけ選択でも）が太くなる

図全体をそのまま貼ると「今どこの話をしているのか」が読み手に伝わらない。
関係する数件だけを選んで書き出した図なら、 **PR やイシューの説明にそのまま貼れる。**
切り取りではなく全体を薄く残すのは、 選んだチケットが全体のどこに位置するかを一緒に伝えるため。

点灯は 2 段になっている。 **選んだものとその隣接（依存元・依存先） = そのまま / それ以外 = 沈む。**
hover したときも同じ規則で光る。 隣接を同じ濃さで残すのは、 選んだものだけを残すと
前後に何が繋がっているのかが読めなくなるため。 「自分が選んだのはどれか」は
選択枠の色と太くなった依存線で見分ける。

hover や選択では依存を辿って連結成分ごと光らせはしない
（一本鎖の stacked PR では 1 件選んだだけで全点灯になり、 絞り込む意味が消えるため）。
チェーン全体を見たいときは次のトレースを明示的に使う。

## トレース・NEXT ツアー・シェアカード

- **上流 / 下流トレース** — 詳細パネルの「⇠ 上流を点灯」「下流を点灯 ⇢」で、 そのチケットから
  依存を**推移的に**辿って点灯する（それ以外は沈む）。 stacked PR で
  「これが詰まると何が止まるか」「これは何に詰まっているか」を一目にする。
  もう一度押すか Esc、 または図の解除ボタンで戻る。 `?trace=up:<id>` / `?trace=down:<id>` で URL 共有できる
- **NEXT ツアー** — 図の「▶ NEXT」か `N` キーで、 NEXT 1 → 2 → 3 を順に選択 + センタリングして巡る。
  1 歩ごとに詳細パネルへその 1 件が出るので、 読みながら次の一手を確認できる。
  最後まで行くと選択を解いて全体フィットに戻る
- **シェアカード** — ヘッダーの「カード」で **1200×630 (OGP と同じ比率) の PNG** を書き出す。
  タイトルと更新時刻が上に入り、 図は残りの領域に全体フィットする。
  選択やトレースの点灯もそのまま焼き込まれるので、 「ここの話」というカードが 1 クリックで作れる
- **キーボード** — `/` = 検索へ / `F` = 全画面 / `N` = ツアー / `Esc` = 1 段戻る
  （全画面 → トレース → ツアー → 選択の順に解く）。 `prefers-reduced-motion` も尊重する

## 速さのための作り

体感速度を仕様として扱っている。 **ユーザーが HTML を受け取るまで 5 ターン以内・1 分以内**、
検証はバックグラウンドで走らせて待たせない。

| 仕掛け | 効果 |
| --- | --- |
| `collect.mjs` が **GraphQL 1 往復**で全部取る | PR ごとに `gh` を叩くと本数に比例して遅くなる。 1 往復なら約 1 秒 |
| `epics` / `next` / `col` / `status` に**既定を入れる** | エージェントがレイアウトを先回りして考えない |
| **overlay** で差分だけ書く | 数 KB の JSON を書き直さず、 足すものだけ 10〜20 行 |
| 生成物に **`__verify()` を同梱** | 検証が `browser_evaluate` 1 回で終わる。 チェックスクリプトを組み立てない |
| 実行時エラーをページ内に溜める | コンソールを別途読みに行く往復が要らない |
| エラーメッセージに**直し方を書く** | 「どう直すか」を考えさせない |

## 生成されるもの

`.local/status-board/<yyyy-MM-dd-HH-mm>.html` の **1 ファイルだけ**。 中間ファイルはスクラッチパッドに置く。
外部依存は Google Fonts の `<link>` のみで、 オフラインでもフォールバックフォントで読める。

## 同梱リソース

| パス | 役割 |
| --- | --- |
| `scripts/collect.mjs` | GitHub / git から `board.json` の下書きを作る。 生の出力を context に載せない |
| `scripts/build-board.mjs` | `board.json` (+ overlay) を検証してテンプレートに差し込み、 1 ファイルを書き出す |
| `scripts/serve.mjs` | 検証用の静的サーバ。 Playwright MCP は `file://` を開けないため必要 |
| `assets/board-template.html` | 出力の雛形。 データ部以外は出力とまったく同じ |
| `references/data-schema.md` | `board.json` / `overlay.json` の書式と検証規則 |
| `references/review-checklist.md` | 検証手順と `__verify()` が見ている項目 |

## プロジェクトの前提

- git リポジトリであること。 GitHub なら PR / issue も拾う
- **言語・フレームワークは問わない**

## 前提条件

- `node` (ESM が動くバージョン)
- `git`
- 任意: `gh` (GitHub CLI、 認証済み)。 無ければ git ローカルの情報だけで作る
- 任意: Playwright MCP。 無ければ検証を飛ばし、 その旨を報告する
- 出力先 (`.local/`) を `.gitignore` しておくと作業ツリーが汚れない
  （スキルが起動時に確認して、 されていなければ提案する）

## 制約

- SVG / PNG の書き出しに Google Fonts は焼き込まれない。 開いた環境にフォントが無いとフォールバックになる
- 図は依存グラフ固定。 他の図種には切り替えられない
- 依存線は左レーンから右レーンへの向きだけ。 同レーン・逆向きは経路が破綻するため弾いている
- 前回結果とのマージはしない。 毎回フル再生成する（確認欄の回答だけは `localStorage` 経由で残る）
