# ループを抜けたあとの全体チェック

参照実装の運用 skill の全体チェック用プロンプト【実績】の汎用化。ユーザが「一通り終わってループを抜けたら、全体の操作・目視チェックをお願いしたい」と頼んでいるときだけ行う。担当の分け方（下の表）は参照実装の例で、自環境の画面・機能に合わせて変える。

## 進め方

1. 5 つの担当を並列（最大 5）で起動する。`model: sonnet`、effort `high`（docs 点検は `medium` でよい）。全員、読むだけ + 小さな不具合の最小の修正。ヘッドレス・偽データ（`{禁止}` を守る。実データ・本物のプロファイルは使わない）。スクリーンショットは `{tmp}/fullcheck-{担当}/` に置き、Read で見る。
2. 担当のうち、テスト総点検は 20 分以上かかる。10 分ごとに確認し、30 分を超えたら期限（10 分）を伝える。
3. 全員の報告が出たら、不具合の一覧（直したもの・残ったもの）をまとめる。
4. **修正の回**を、1 人のサブエージェントで行う（他の Agent が同時に編集して衝突しないよう、1 人だけ）。
5. ユーザの判断待ちのもの（設計の大きな変更、確認コマンドの分離など）には触れない。一覧にして報告する。
6. 最後に `{確認コマンド}` が全部通ることを確認し（修正の回の担当に実行させるか、自分で実行）、ユーザに報告する。

## 共通部分（5 担当すべてに入れる）

```
あなたは {app} の全体チェックの担当「{担当名}」です。{CLAUDE.md などの最初に読むもの} を最初に読むこと。
ここ数日、feedback のループで多くの変更が入りました。それらの結果として、{担当の範囲}に壊れ・不整合・見た目の崩れ・古い記述がないかを、操作と目視で点検してください。
- ヘッドレス（偽物・一時データ・一時ディレクトリの設定の写し。プロファイルの場所も一時に）で動かす。スクリーンショットは {tmp}/fullcheck-{担当}/ に置き、Read で見る。実データが写らないこと。
- 小さな不具合は最小の変更で直す（共有ファイルは書き込む直前に読み直し、他の人の変更を消さない。他の担当が同時に動いている）。大きいもの・判断が要るものは直さず一覧にする。
- 禁止: {禁止}（置き場の記録と既存の実行記録の変更を含む）。
- 報告（日本語）: 見つけた不具合の一覧（直した/直していない、根拠のファイルとスクリーンショット）/ 変更したファイル / テスト結果 / ユーザの判断が要る点。
```

## 5 つの担当（`{担当の範囲}`）

| 担当 | 範囲（参照実装の例 → 自環境） |
|---|---|
| トップ画面 | トップ画面全体: 主要カード・日付や期間の切り替え、一覧と開始、ダークモード・狭い幅を含めた見た目、各ボタンの動き |
| 詳細・ログ | 実行ログ（進捗・表示・中断・再開・削除）と詳細画面（markdown 表示・画像ビューア・パスリンク・編集） |
| フィードバックと設定 | フィードバック機能（要素の選択・節のオプション・保存先への追加・コピー・スクリーンショット）と設定画面（各キー・検証メッセージ・アプリ内通知） |
| テスト総点検 | 確認コマンドが通ること。落ちるテスト・揺れるテスト（再現率を数える）・ソース文字列を正規表現で検査していてリファクタリング後に合わないテスト・重複・遅いテストの棚卸し。落ちる原因が本物の不具合ならその修正、テストが古いならテストの更新。層の分離は提案だけで、実施しない |
| docs 点検 | 正本 README・`docs/`・`CLAUDE.md` のリンク切れ、実在しないファイル名・コマンド・設定キー、変更後の挙動との食い違い。運用手順書の規則は変更しない（誤字・リンクの修正と、不整合の報告のみ） |

## 修正の回のプロンプト

```
あなたは {app} の「修正の回」の担当です。他の Agent は同時に編集していません。あなただけがソース・docs を編集します。{最初に読むもの} を最初に読むこと。
次は、全体チェックの 5 担当が報告した「直していない不具合」の一覧です。
{未修正の不具合の一覧（担当・内容・根拠のファイルやスクリーンショットのパス）}

- 上から順に、小さなものを最小の変更で直す。直したらその都度、関連のテストを確認する。
- 触れない（直さず「判断待ち」として報告）: {ユーザの判断待ちの項目}。
- 最後に {確認コマンド} を実行し、全部通ることを確認する。揺れるテストは、少し置いて単独で再実行し、再現率を報告する。見た目を変えたら、ヘッドレスのスクリーンショットを {tmp}/fullcheck-fix/ に置き、Read で見る。
- 禁止: {禁止}
- 報告（日本語）: 直したもの / 直さなかったもの（理由）/ 変更したファイル / 確認コマンドの結果 / ユーザの判断が要る点。
```
