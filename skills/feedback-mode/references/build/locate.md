# 場所を一意に指す（Web）

構築側の資料。凡例・用語は `references/concepts.md`。選んだ要素・テキストを、読む Agent が**ソースの 1 か所**と**今のページ上の 1 か所**に迷わずたどれるようにする手がかりの作り方。部品の名前（`data-fb` の道筋）だけでは足りないとき、とくに docs サイトのように「どの段落か」「ソースの何行目か」が効くページで使う。

出どころ: Web 参照実装（Astro 7 + Starlight の docs サイトに、この skill の build を取り込んだ版）【実績】。コードの例はその縮小版で、ひな形 `assets/templates/web/astro/feedback-app.ts` の `xpathOf` / `selectorOf` が同じ考え方の最小形。

## 1. 手がかりの種類と、記録への書き方

| 手がかり | 何に効くか | 記録（`target.*` → 「選んだ位置」節・frontmatter） |
|---|---|---|
| XPath | 今のページ上の同じ要素に戻る。id があればそこを起点に、無ければ `/html[1]/body[1]/…` の index 付き | `target.xpath` |
| CSS セレクタ | 同上。人が読んで場所の見当がつく。短いものを選ぶ | `target.selector` |
| テキストフラグメントの URL（`#:~:text=開始,終了`） | テキストの**範囲**まで戻る。ブラウザで開けばその文がハイライトされる | `target.fragment` |
| ソースの行（`path:12-14`） | 元の Markdown / MDX の何行目か。Agent はそのまま開いて直せる | `target.source`（frontmatter の `source` にも） |
| 近くの見出し・ランドマーク | 人と Agent が文脈をつかむ（「## 手順 の 2 つ目のリスト」「サイドバー」） | `target.state` などに自由に |

## 2. XPath と CSS セレクタは、保存の前に引き直す【実績】

作ったら、その場で `document.evaluate` / `querySelectorAll` で引き直し、**ちょうど 1 つ、しかも元の要素**に当たることを確かめる。当たらなければ**書かない**（null）。間違った場所を指す手がかりは、無いより悪い（Agent が別の段落を直す）。

- XPath: id が一意な祖先を見つけたらそこで止めて `//*[@id="…"]` から。id に `"` を含むものは起点にしない。HTML 以外の名前空間（SVG など）は `*[local-name()="…"]`。
- CSS セレクタ: 候補を「起点（一意な id・ページに 1 つのランドマーク・フレームワークの安定した class）+ 末尾 k 段」で複数作り、一意に当たる中で一番短いものを選ぶ。最後の保険に `html > body > …` の全段。**ビルドごとに変わる class（ハッシュ付き・ユーティリティ CSS）は使わない**。安定した class の接頭辞を許可リストにする（Starlight なら `sl-`）。
- 兄弟の中での見分けは `:nth-of-type(n)` / `[n]`。同じ名前の兄弟が 1 つなら付けない（短くなり、前に要素が増えても壊れにくい）。

## 3. テキストフラグメントの URL【実績】

テキストを選んだときは、範囲を `#:~:text=` の URL にする（ブラウザがその文までスクロールしてハイライトする。Agent も文字列で検索できる）。

- 短ければ全文、長ければ先頭と末尾（`開始,終了`）。区切りは**単語の境界**でしか一致しないので、`Intl.Segmenter`（`granularity: 'word'`）で境界に寄せる。日本語もこれで切れる。
- 先頭の文字列がページに複数あれば、直前の文字を `prefix-,` に足し、「prefix + 開始」がページで 1 つになるまで 12 → 24 → 48 → 96 字と伸ばす。ブロックの先頭から始まるときは、直前のブロックの最後の行を prefix にする。
- `-` と `,` は区切りなので必ず `%2D`・`%2C` にエンコードする（`encodeURIComponent` は `-` をそのまま残す）。

## 4. ソースの行: Markdown の処理に行番号を付ける（任意の手）【実績】

Markdown / MDX から作るページ（docs サイト・ブログ）では、**dev のときだけ** Markdown の処理に小さなプラグインを差し、本文の要素に `data-fb-src="<path>:<開始行>-<終了行>"` を付ける。ブラウザ側は選んだ要素からこの属性を拾う。

- 付ける要素: 見出し・段落・リスト・表・引用・コードブロックと、MDX のコンポーネント（Aside・Tabs など）。位置は hast の `node.position`（mdast から引き継がれる）。パスはリポジトリ直下からの相対。
- 拾い方（選んだ要素から）: 要素自身 → 子孫の範囲をまとめたもの → 最も近い祖先 → 直前の兄弟、の順。自身に無くても子孫が持っていれば、祖先より正確。テキストの範囲は開始と終了それぞれから拾い、同じファイルなら開始〜終了にまとめる。どこから拾ったかも書く（「祖先から」「直前の兄弟から推定」）。
- 落とし穴【実績】:
  - **Astro 7 の Markdown は rehype ではなく Sätteri**。`markdown.rehypePlugins` に足しても効かない。`astro:config:done` で `config.markdown.processor`（`name === 'satteri'`）の `options.hastPlugins` に差す。Sätteri でなければ警告を出して付けない。
  - コードブロックを別の木で置き換える統合（expressive-code など）は、付けた属性を消す。`pre` の位置を順に控えておき、置き換えの**後ろ**に足したプラグインで付け直す。
  - mdast の段階で html ノードに差し替える統合（mermaid など）は hast に属性を付けられない。その統合より**前**に走る mdast プラグインで、同じ形の html に属性を付けて差し替える。
  - 他の統合が processor に足し終えた後で差す（`astro:config:done`）。前に付ける（`unshift`）か後ろに付ける（`push`）かを、上の 2 つで使い分ける。
- 本番から外す: `command === 'dev'` のときだけ差す。属性名（`data-fb-src`）を本番の dist の検査パターンに入れる（`check-no-dev-tools-in-dist.sh` の既定に入っている）。
- 他のフレームワーク（remark / rehype を直接使う、Vite のプラグインで Markdown を変換する等）でも、「位置付きの木に dev だけ属性を足す」考え方は同じ【未検証】。

## 5. 引き直しの順（メモの印・「場所を表示」）【実績】

保存した手がかりから、今のページ上の場所を引き直すときは **XPath → CSS セレクタ → テキストフラグメント → ソースの行** の順に試し、最初に当たったものを使う。テキストの選択は、範囲まで戻せるテキストフラグメントを先に試す（XPath・セレクタは範囲を含む要素までしか戻せない）。ソースの行は「範囲が一致 → 範囲を含む（狭い順）→ 重なる（狭い順）」で最も合う要素を選ぶ。どれも当たらなければ「見つからない」と出す（ページが書き換わった。メモの欄は残す）。

## 6. 古さ（`dirty` / `stale`）【実績】

ソースの行を書くなら、受け口（ソースと git が見える側）が保存のときに次を足すと、loop が「すでに直っていないか」を先に確かめられる（記録の形は `references/concepts.md`）。

- `dirty`: `git status --porcelain -- <ソース>` が空でなければ true。行番号は commit ではなく作業ツリーのもの。git が使えなければ書かない。
- `stale`: ソースの mtime が、画面を開いた時刻（ブラウザの `performance.timeOrigin` を `pageOpenedAt` で送る）より新しければ true。分からなければ書かない。**立つ条件は狭い**（`references/loop/lessons.md`「stale が立つ条件は狭い」）。
- dev サーバーの起動時刻と、統合のソースのハッシュ（起動時と保存時）も記録に書いておくと、「統合を直したのに dev を再起動していない」が記録から分かる。
