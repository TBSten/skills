# 静的な HTML（agent が作るレポート・チェックリスト）にフィードバックを付ける

構築側の資料。対象は**アプリではなく、agent が作って人に渡す 1 枚の HTML**（調査レポート・導入のチェックリスト・設計の比較表など）。サーバーも置き場も無い。人は HTML を開いて項目にコメントし、まとめてコピーしてチャットに貼る。agent は貼られた文を読んで HTML のデータを直す。凡例・用語は `references/concepts.md`。

【実績: Web 参照実装】参照実装の 2 つ目のプロダクトで、agent がプロジェクトを調べて書く「コードベースのレポート」と「導入のチェックリスト」（どちらも 1 枚の HTML）に入れた。「ここが違う」をチャットで場所ごとに説明してもらうのが大変、が出発点。

## 1. アプリのフィードバックモードとの違い

| | アプリ（`build.md`） | 静的な HTML（ここ） |
|---|---|---|
| 書く人・読む人 | 人が書き、loop が読む | agent が作った HTML に人が書き、同じ会話の agent が読む |
| 置き場（Sink） | ファイル・HTTP など | **無い**。ブラウザの `localStorage` に溜め、クリップボードで渡す（`concepts.md` の作り方 (c)「会話に貼る」） |
| 宛先 | 部品・ソースの行 | **HTML の中の JSON の場所**（`roles[name=ViewModel]`）。agent が直すのは JSON だけ |
| 本番から外す | 要る | 要らない（HTML そのものが人に渡す成果物。ただし送り先は人のクリップボードだけ） |
| スクショ・ログ | 付ける | 付けない（文と場所だけで足りる） |

## 2. HTML の作り【実績: Web 参照実装】

- **データは HTML の中の JSON だけ**。`<script type="application/json" id="report">` に置き、HTML の残りは描く殻。agent が読み書きするのは JSON の行だけ（開始タグと `</script>` はそれぞれ 1 行に置き、agent が `sed` で切り出せるようにする）。殻はテンプレートのまま、データが入った後に作り直さない。
- 宛先にしたい要素に `data-fb="<JSON の場所>"` と `data-fb-label="<画面での名前>"` を付ける。入れ子にしてよく、ラベルは外側からつないで「4. 要素 › app › ViewModel」と出す（ラベルが無ければ直下の見出しの文字）。表の行・セルごとに付けると、セル単位で指せる。
- JSON の場所の書き方は導入先で決めて、agent への手順書に書く。例: `roles[name=ViewModel]`（配列の中で `name` が一致する要素）・`roles[name=ViewModel].forbidden[0]`・`overview.language`（キー）・`page`（ページ全体）。
- 人への質問（選択肢と推奨）も同じ HTML に置けば、回答とフィードバックを 1 回のコピーで渡せる（§4）。
- 外部のスクリプト・フォントに頼らない（ファイルを開くだけで動く。オフラインでも）。JS は HTML の中に書く（レポートとチェックリストのように複数あれば、同じ JS をそれぞれに置く）。

## 3. フィードバックモードの操作【実績: Web 参照実装】

- 右下の「フィードバック」で入る。帯に「コメントしたい項目をクリック（文字をドラッグで引用、Shift + クリックで複数）」。
- **クリックで宛先を選ぶ → その場に入力欄**。Shift + クリックで同じコメントに宛先を足す・外す（上限 20。`interaction.md` §6 と同じ）。
- **引用**: 文字をドラッグで選んでから書くと、選んだ文字が「引用」として宛先に付く（300 字まで）。
- **いまの内容**: 引用が無ければ、保存した時点のその場所の文（120 字まで）を「内容」として付ける。agent は JSON が今もそう書いてあるかで、自分が後から直したかを見分けられる。
- **書きかけ**: 保存していない文は宛先ごとに `sessionStorage` に残す（再読み込み・閉じて開き直しでも戻る。保存したら消す）。入力欄の外をクリックしても**黙って消さない**（参照実装のレビューで「高」になった）。
- 入力欄はドラッグで動かせ、位置を覚える。入力欄を開いても**ページを宛先の下端まで飛ばさない**（大きな節を選ぶと数千 px 飛んだ）。
- モード中も、畳んだ `<details>` は開ける（宛先を選ぶのと開閉をぶつけない）。閉じた `<details>` の中のコメントは、いちばん外の閉じた見出しに印を出す。
- 保存したコメントは `localStorage`（キーにページの URL）に溜め、ページの上に番号の印を出す。一覧で直す・消す。保存できないとき（プライベートウィンドウなど）は一覧を開いて知らせ、すぐコピーするよう促す。

## 4. 渡すメニュー【実績: Web 参照実装】

回答かフィードバックが 1 つでもあると、右下に**1 つだけ**小さなメニューが出る（回答用とフィードバック用に分けない）。

- 「まとめてコピー」: 回答とフィードバックを 1 つの文にしてクリップボードへ。**まだ渡していないものだけ**を入れ、全部渡し済みなら全部をもう一度。いま入る件数をメニューに出す（「フィードバック 3 件（うち 1 件は新しい）」）。
- 「JSON で保存」: 回答を JSON のファイルで保存（チャットに貼れないとき）。
- 「コピーされる内容を見る」: 貼る前に中身を見せる（はみ出さないよう折り返す）。
- 「すべて消す」: 回答とフィードバックを消す。トーストの「戻す」で取り消せるようにする（確認なしで消すとレビューで指摘された）。
- コピーに失敗したら中身を読み取り専用の欄に出して全選択し、手でコピーしてもらう。成功はトーストだけで知らせる。
- メニューの高さを CSS 変数に入れ、右下のボタン・一覧をその上に逃がす。sticky な欄が本文の質問に重ならないようにする。

## 5. コピーされる文の形【実績: Web 参照実装】

agent が迷わず読めるよう、1 行目に「どのファイルへの、何件のフィードバックか」と「対象は JSON の場所」を書く。

```text
コードベースのレポート（report.html）へのフィードバックです（2 件）。「対象」はこのファイルの JSON の場所です。直して、直せないものは理由を返してください。

1. 4. 要素 › app › ui › ViewModel
   対象: roles[name=ViewModel]
   > feature モジュールにも ViewModel がある（feature/*/src/...）

2. 1. 概要 › 主なフレームワーク ほか 1 件
   対象: overview.frameworks（1. 概要 › 主なフレームワーク）
   内容: 「Compose, Koin」
   対象: overview.targets（1. 概要 › ターゲット）
   引用: 「Android」
   > バージョンも書いて
```

- 宛先が複数（Shift + クリック）なら `対象:` が複数行になり、括弧に画面での名前を添える。
- `引用:` は人が選んだ文字（そこについてのコメント）、`内容:` は保存した時点のその場所の文。どちらかが付く。
- 回答があれば同じ文の先に、どのファイルへの回答か・まだ答えていない質問の id・`{"target": "...", "answers": {"q1": {"answer": "…", "note": "…"}}}` の JSON ブロックを置く。

## 6. agent 側の手順（HTML を作る skill の手順書に書く）

1. 貼られた文の 1 行目でファイルを決め、`対象:` ごとにその JSON の場所を直す（事実が違うと言われたらコードを見直す）。直さないものは理由を返す。
2. `内容:` と今の JSON が違えば、自分が後から直した可能性を考える。
3. 回答は JSON の `answers` に id で写す（`note` が `null` なら選択肢を選んだだけ）。
4. 直した宛先を人に伝える。人のブラウザのコメントは人が消すまで残る（agent からは消せない）。
5. JSON を書いたら必ず読み戻して検証する（`jq`・`python3 -m json.tool` など）。壊れた JSON はページの先頭にエラーとして出るようにしておく。

## 7. 確かめること

- PC とスマホ幅で: 宛先を選ぶ → 書く → 保存 → 印が出る → まとめてコピーの中身が §5 の形。コンソールのエラー 0・横スクロール 0。
- 書きかけが、外側のクリック・再読み込み・閉じて開き直しで消えない。大きな節を選んでもページが飛ばない。
- 2 回目のコピーは新しいものだけ。全部渡し済みなら全部。
- `localStorage` が使えない状態（プライベートウィンドウ）で、保存できないことが見え、コピーはできる。
- スマホ幅で、帯が進捗バーなど固定の要素を隠さない。
