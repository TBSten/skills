# Review の UI（印と popup）を作る

構築側の資料。ファイルの形・ボタンの意味・cli は `review.md`。ここは画面の決まりだけを書く。コードの雛形は無い（参照実装は Astro の Dev Toolbar アプリで、ページの部品に強く依存するため）。受け口は `scripts/review.mjs` を import して作る。

【実績: Web 参照実装】の決まりのうち、場所に依らないものだけを残した。導入先の画面（Web・アプリ・エディタ）に合わせて読み替える。

## 0. 前提

- **dev / debug のときだけ出す**。本番の成果物に入れない（`references/build/build.md` §0 と同じ。本番検査の grep に Review の目印も足す）。
- 入口はフィードバックモードと同じ場所（Dev Toolbar・debug menu）に「Review」を 1 つ足す。**既定は隠したまま**。出しているあいだはタブ（セッション）の中で覚え、画面を移っても出し続ける。
- 受け口は `createReviewStore({ inbox, root, filePrefix })` の `load` / `resolve` / `reopen` / `remove` / `send` / `addAction` / `updateAction` / `removeAction` をそのまま呼ぶ。ファイルは開くたび・タブに戻るたびに読み直す（dev サーバーを立て直さない）。

## 1. 印（画面の上）

- 指摘の場所（file・line を今のソースに合わせた行）に、番号の印と枠を出す。色は優先度の段（p7 以上 赤・p5〜6 橙・p3〜4 黄・それ未満 灰・無し 藍）。
- ファイル全体への指摘と、画面に出ない行（frontmatter・コメントなど）への指摘は、画面の見出しに印を出す。
- quote が見つからない指摘（`place: lost`）は書かれた行のまま出し、popup に「もう直っているかもしれません」と出す。
- 隠れている場所（閉じた折りたたみ・選ばれていないタブ・畳んだコード）の指摘は、開くときに見えるようにしてからスクロールする。
- 固定ヘッダーの下に印を隠さない。

## 2. 一覧

- 右上（スマホは畳むと右上の小さな札、開くと下から）。この画面の指摘・ほかの画面の件数・画面の無いファイル・読めない指摘を分けて出す。
- 絞り込み: 優先度・ユーザ影響（`impact` のある指摘があるときだけ）・解決済みも出す。
- 行に乗せると、画面の上のその印と枠を目立たせる。解決済みの行には、押したボタンの札と一言を添える。
- 一覧の高さは止めて、中身だけスクロールする。

## 3. popup

- 印か一覧の行を押すと開く。印と popup を線でつなぐ。
- **max-height を決めて、本文だけ overflow-y: auto**（ボタンを画面の外に押し出さない）。右下に小さく薄く「何件め / 総数」（絞り込み後の全体）。
- 本文の上: 場所（押すと `file:line` をコピー）・「開く」（エディタのその行。Vite / Astro の dev サーバーの「エディタで開く」など）・`impact` の札（あり = 色付き、なし = 灰の点線）と理由・agent の一言（`ai-note`）。
- ボタン: 解決済みにする・直さない・直してもらう・人が足した選択肢（点線の枠）・「＋」。`recommend` があれば各ボタンの文字の横に「推奨 8」を**小さく薄く**（押すかどうかは人が決める）。
- 一言の欄は 1 行。**IME の変換の確定の Enter で送らない**（`isComposing` を見る。Safari は keydown の順が違う）。
- 前・次（画面をまたぐときはその画面へ移ってから開く）、← → でも動く、Esc と × で閉じる。選択肢の編集中の Esc は編集だけを閉じる。
- `<画面>#review=<id>` で開くと、隠していても出してその指摘を開く（人に 1 件を見てもらうときに渡す。`review.mjs show --link` が作る）。
- ソースを直して画面が読み直されても、開いていた指摘・書きかけの一言・本文のスクロールを保つ。quote で今の行を探し直すので、直して quote が消えれば「もう直っているかもしれません」になる。

## 4. ボタンを押したあと

- 「解決済みにする」などは**次の指摘へ進む**。トーストの「戻す」で取り消せる（`reopen`）。保存中と進んだ直後は押せない（連打で次の指摘まで解決済みにしない）。
- 次がほかの画面の指摘なら、画面は移らずに閉じ、トーストの「次の画面 ›」で移る。最後の 1 件を解決したら知らせる。
- PC のトーストは popup の上に出す（次の指摘のボタンを覆わない）。
- 「直してもらう」は `send`。トーストの「戻す」は記録を archive して指摘を未解決に戻す。
- 「直さない」と足した選択肢は `resolve(id, noteOf(名前, 一言))`。

## 5. 選択肢を足す UI

- 「＋」で名前・agent にしてほしいこと・判断の種類（`decision`）を入れる。スマホではボタンの並びと入れ替えて出す（本文をつぶさない）。
- 名前を押すとその場で直せる。消してもトーストの「戻す」で足し直せる。上限（8 個）のときは「＋」を出さない。
- 使えない名前（`labelProblem`）は保存の前に知らせる。

## 6. 確かめること

- `review.mjs check` が OK のファイルで、印が全部出る（読めない指摘・無いファイルは一覧の「読めない指摘」に出る）。
- dev サーバーと cli を同時に書いても消し合わない（lock）。
- 本番の成果物に Review の目印が無い（`scripts/check-no-feedback-in-prod.sh` に目印を足して回す）。
- E2E: 印 → popup → 解決済み → ファイルに `status: resolved` が書かれる、を 1 本（`references/build/interaction.md` の E2E の注意も同じ）。
