# 人間に見せる説明には見た目で分かるものを付ける

PR の本文・チケット (issue / Notion / Linear など) の説明・人間向けのレポートを書くときは、読む人が最初の 1 枚で要点をつかめるように、図・スクショ・動画・実際の出力のどれかを付ける。

## 見せ方は変更の種類で選ぶ

| 変更・内容 | 見せ方 |
|---|---|
| 見た目・出力が変わる | Before / After を実物で並べる (同じ入力で main とこのブランチを撮る) |
| バグ・原因の説明 | 仕組みの図 (タイムライン・競合の順番など) |
| 新しい API・機能 | 1 枚まとめ (書けるコード + 実行結果) |
| 動くもの (CLI・UI) | 実際の実行から作った GIF / 動画 |
| 削除・移動 | 消えるもの / 残るものの図 |
| チケットの起票 (課題・提案) | 現状と目指す姿を並べた図 1 枚 |
| 数行の変更 | diff のコードブロック (画像は要らない) |
| 見た目がない | 実際の出力を `<details>` に入れる |
| CI だけ・設定だけ | 画像なしでよい。確かめ方を書く |

## 作り方

- 1 枚 1 メッセージ。alt に「何が分かる図か」を 1 文で書く。
- 実際の実行・実データから作る。どの PR・コミット範囲・コマンドで撮ったかを書く。モックは作らない。
- 作り方を正直に書く (画面収録 / 実ログから描いた再現 / headless 描画)。
- HTML で描いて Playwright でスクショする (deviceScaleFactor 2〜3)。ダークモード版は `<details>` に入れる。
- 色はプロジェクトのデザインシステムのトークンを使う。スマホ幅 (420px 前後) でも読めること。
- 原本の HTML と PNG はリポジトリの外 (共有フォルダ・`.local/` など) に残す。
- `visual-explanation` skill (`gh skill install tbsten/skills visual-explanation`) が入っていれば、HTML 雛形・撮影・PR への添付・本文チェックはその skill の script で行う。

## 置き場所 (PR)

- 画像は最終ツリーに残さない。
- PR ブランチの `.github/pr-assets/` に画像をコミットし、次のコミットで消す。本文には **そのコミット SHA を固定した** URL を書く:
  - 公開リポジトリ: `https://raw.githubusercontent.com/<owner>/<repo>/<sha>/.github/pr-assets/<file>.png`
  - 非公開リポジトリ: `https://github.com/<owner>/<repo>/blob/<sha>/.github/pr-assets/<file>.png?raw=true` (表示されるか最初の 1 本で確かめる)
- ブランチ名入りの URL は CDN が古い版を返すことがあるので使わない。

## 置き場所 (チケット)

- チケットのツールが画像添付できるならそこに PNG を添付する。HTML を埋め込めるなら HTML 図 1 枚を埋め込む。
- 置き場所に迷ったら PR と同じく SHA 固定 URL を使う。

## 本文での位置

「何をしたか」(チケットなら「背景」) の節の頭に 1 枚目を置く。文章はその補足にする。

## チャットで図を返すとき

スマホで見られるよう、HTML ではなく PNG を添付する。
